01In developmentPrivate repository · 120+ merged PRs

Block-Based Build Instructions

Describe a structure in plain language. Get a locked design, a deterministic voxel model, a bill of materials, and step-by-step instructions you can follow in the browser.

BBI is an AI-assisted design and construction tool for block-based games, with Minecraft first. The language model runs the design workshop and never emits geometry: a procedural generator builds the canonical voxel model from the locked specification, and everything downstream (validation, materials, instruction book) derives from that model.

Works today
  • Design workshop → specification and palette → design lock
  • Procedural generation with a 3D viewer and validation findings
  • Bill of materials, build statistics, block catalog
  • Instruction book: chapters, steps, camera hints, quality checks, change marking
Roadmap
  • Revision engine: change requests with model diffs (phase 5, in progress)
  • Identity provider and first shared deployment
  • Exports and renders for sharing a build
Stack
.NET 10 modular monolith, EF Core, PostgreSQL, Redis, S3-compatible storage · React 19, TypeScript, Vite, Tailwind, Three.js
Process
Five-phase roadmap, one issue per deliverable, architecture decision records, a feature guide page for every shipped feature.

DFS Command Center

A research and portfolio workbench for daily fantasy sports on DraftKings and FanDuel. It consolidates provider exports, public sports data, projections, lineup construction, contest evaluation and results into one audited record.

I built it for myself, which means it gets used every slate. It imports the platforms' real export files (parsers verified against the actual downloads), ingests schedules, rosters, game logs and injury reports from public sources behind a licensing gate, generates lineups under constraints, and reconciles what was actually entered against what the plan said.

What it refuses to do: it never enters a contest or moves money, nothing in it says "profitable", and a feature that isn't ready shows an explicit unavailable state instead of a placeholder that looks real.

Under the hood
  • Constraint solving with OR-Tools CP-SAT, portfolio optimization with HiGHS
  • Monte Carlo contest evaluation with uncertainty reported apart
  • Bitemporal rosters, append-only game logs, a reviewed identity queue
  • Fourteen export gates, every input fingerprinted and re-checked
Stack
Python 3.12, FastAPI, SQLAlchemy, Celery, Polars, SciPy · React 19, TanStack Query, Tailwind 4 · Docker Compose, Prometheus
Personal data stays personal, so there's no public instance. Happy to show the synthetic workspace.

Open Editor Platform

A plan for a fully open-source editor SDK that gives software developers and book authors equal standing: one integration surface, two editing profiles, a shared platform for comments, versions, search and optional AI.

The recommendation is to reuse what already works (CodeMirror 6 for code, Tiptap's open-source packages on ProseMirror for manuscripts, Yjs for collaboration) and to own the contracts around them: a book model with stable chapter IDs, portable schemas, conversion fidelity for DOCX and EPUB, and release gates that are published rather than promised.

Honest note: the plan is sized for a team of eight to ten. I'm working out what a one-person first slice looks like, and whether to start it in the open.

In the plan
  • Survey of CodeMirror, Monaco, Ace, ProseMirror, Lexical, Slate and friends
  • Three-layer product: surfaces, capability packages, workspaces
  • Architecture contracts for documents, collaboration and AI proposals
  • Release gates, benchmarks and a twelve-month delivery plan
Proposed stack
TypeScript, CodeMirror 6, Tiptap OSS / ProseMirror, Yjs, Hocuspocus, Web Workers first; Apache-2.0 for new code

04PrototypeRuns locally · no customers

The DevOfCodes platform, and Falcon

A multi-tenant SaaS foundation I built to learn what a security-first platform costs to get right, with Falcon, a project and task manager for engineering teams, as the first service on top of it.

Seven deployable services from one compose file: Identity (OpenID Connect, MFA, step-up auth), a Control Plane for plans, entitlements and a service registry, a Gateway that validates tokens and enforces policy and rate limits at the edge, an append-only Audit store, and Falcon itself with PostgreSQL row-level security per tenant.

Falcon works end to end on my machine. It has no users, and I'm not selling it. The platform underneath is what I keep: it's the foundation for the next product, and a game experiment (GridForge) already reused it by treating each world as a tenant.

Stack
.NET 10 with OpenIddict · NestJS 11 on Fastify · PostgreSQL with RLS · Redis · RabbitMQ · BullMQ · React 19 · Prometheus and Grafana
Status
Working prototype. Not deployed. Kept as the base for future products rather than marketed as one.
