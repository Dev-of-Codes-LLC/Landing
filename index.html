DFS Command Center

A research and portfolio workbench for daily fantasy sports on DraftKings and FanDuel. It consolidates provider exports, public sports data, projections, lineup construction, contest evaluation and results into one audited record.

I built it for myself, which means it gets used every slate. It imports the platforms' real export files (parsers verified against the actual downloads), ingests schedules, rosters, game logs and injury reports from public sources behind a licensing gate, generates lineups under constraints, and reconciles what was actually entered against what the plan said.

What it refuses to do: it never enters a contest or moves money, nothing in it says "profitable", and a feature that isn't ready shows an explicit unavailable state instead of a placeholder that looks real.

Under the hood
  • Constraint solving with OR-Tools CP-SAT, portfolio optimization with HiGHS
  • Monte Carlo contest evaluation with uncertainty reported apart
  • Bitemporal rosters, append-only game logs, a reviewed identity queue
  • Fourteen export gates, every input fingerprinted and re-checked
Stack
Python 3.12, FastAPI, SQLAlchemy, Celery, Polars, SciPy · React 19, TanStack Query, Tailwind 4 · Docker Compose, Prometheus

Block-Based Build Instructions

Describe a structure in plain language. Get a locked design, a deterministic voxel model, a bill of materials, and step-by-step instructions you can follow in the browser.

BBI is an AI-assisted design and construction tool for block-based games, with Minecraft first. The language model runs the design workshop and never emits geometry: a procedural generator builds the canonical voxel model from the locked specification, and everything downstream (validation, materials, instruction book) derives from that model.

Works today
  • Design workshop → specification and palette → design lock
  • Procedural generation with a 3D viewer and validation findings
  • Bill of materials, build statistics, block catalog
  • Instruction book: chapters, steps, camera hints, quality checks, change marking
Roadmap
  • Revision engine: change requests with model diffs (phase 5, in progress)
  • Identity provider and first shared deployment
  • Exports and renders for sharing a build
Stack
.NET 10 modular monolith, EF Core, PostgreSQL, Redis, S3-compatible storage · React 19, TypeScript, Vite, Tailwind, Three.js
Process
Five-phase roadmap, one issue per deliverable, architecture decision records, a feature guide page for every shipped feature.

The DevOfCodes platform, and Falcon Prototype

Work with me

Four kinds of project I can deliver with confidence.

Each one is something I've already done for myself, which is the only kind of promise I'm comfortable making on a page like this.

Build a small web application, end to end

Spec, data model, API, UI, auth, and a Docker deployment you can run anywhere. Typically .NET or Node on the back, React on the front, PostgreSQL underneath.

Evidence: BBI, the platform

Turn a messy data workflow into a reliable pipeline

Imports from awkward files, validation that opens issues instead of silently fixing things, provenance on every row, scheduled jobs, and reports people can trust.

Evidence: DFS Command Center

Finish or harden something you already have

Authentication, multi-tenancy, background jobs, observability, tests and documentation for a codebase that works but isn't yet something you'd hand to a stranger.

Evidence: the platform, BBI's cross-cutting track

Set up an AI platform, or build AI into your product

Model APIs connected to your own data and systems, with the parts that make it dependable written as code: structured outputs, tool calls, permission boundaries, evaluation sets, cost limits, and logs you can audit. Or a working setup for your team's AI coding tools: shared instructions, MCP servers into your systems, and review rules that keep the output something a person can check.

Evidence: BBI's design workshop, where the model shapes the spec and deterministic code builds everything else

How an engagement runs

  • A short call, then a written scope with acceptance criteria you can check without reading code.
  • Fixed-scope quote. Work lands in units, each merged with its tests and docs.
  • A written status record as I go, so you always know what exists and what doesn't.
  • You own the code and the repository from day one.
  • I use AI coding tools heavily and under strict process. You'll see the process, not just the output.
Good fit: a well-defined project of a few weeks to a couple of months for a founder, a small team, or an engineer who needs a second pair of hands. I work on DevOfCodes projects outside a full-time job, so schedules are quoted with that in mind.

Not a fit: open-ended staff augmentation, anything that needs daytime on-call, or a project that needs a team.
