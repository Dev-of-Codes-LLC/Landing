The rules they follow

A prompt is easy. Knowing where it stops is the work.

Every skill and agent in the set is held to the same five rules. They are written into each file, not left to a README.

01

Read-only by default

A digest reads. A planner reads. Anything that writes says exactly which one write it makes.

02

Drafts, not actions

Agents return tickets and plans for a person to approve. They never file, merge or close on their own.

03

Data is not instructions

Text in issues, pull requests and web pages is reported, never obeyed. In a public repo anyone can write there.

04

Every fact has a date

"Checked 2026-10-10: …" or it is a guess, and a guess is labelled as one.

05

Dry run first

Destructive steps print the exact commands and wait. Data nobody named is never deleted.

after-action

Reviews a failed release, UAT round, deploy or deadline in the voice of a blunt SEAL task-unit commander. It reads the evidence itself, turns every excuse into something the team controls, and gives exactly three fixes, the first one first. Inspired by Extreme Ownership.

Fixed debrief formatEvals included

Won'tedit code or file anything during the review, name or blame a person, or state a cause it could not trace to evidence.

How it fits together

One loop, from idea to write-up.

The pieces are useful alone. Together they keep a small backlog honest without anyone having to remember it.

  1. ticket-writer

    An idea becomes one issue with one outcome and the exact steps.

  2. you + the AI

    The work happens in a branch, under the issue's acceptance criteria.

  3. land-branch

    Rebased, checked, merged, and the local stack rebuilt.

  4. feature-doc

    What shipped is written up for the wiki and for the people who asked.

status-digest · twice a weekreads all of it and feeds what's red, stale or overdue back to the top. backlog-planner turns the bigger items into drafts.

Getting started

  • Add the marketplace and install one or both plugins with the commands at the top of this page.
  • The devofcodes-repo-ops skills ask for a toolkit.json the first time. Copy the one in examples/acme to start.
  • Prefer to read first? Every skill is a folder with one SKILL.md. Copy the ones you want into .claude/skills/.

Plain facts

  • These were built for a one-person company. Your team may want more approvals, not fewer.
  • The devofcodes-repo-ops skills assume GitHub and the gh CLI. The Docker scripts run on Windows PowerShell 5.1, and on PowerShell 7 on macOS and Linux. CI runs them on Linux.
  • They are written for Claude Code. The rules and patterns carry over to other agents; the install steps do not.
  • Issues and pull requests are welcome. I review them myself, so expect days, not hours.

I also lean on skills I didn't write, and they stay with their authors: Anthropic's skills, Vercel's web interface guidelines, and the AWS plugin. They are not in this repo.
